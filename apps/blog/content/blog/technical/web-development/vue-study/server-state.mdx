## 1. useUser(id) và abort [#use-user]

Bài 2 đã có `watch` cộng `AbortController`. Bài 8 đã có hình dạng composable. Ghép lại:

```ts
export function useUser(id: MaybeRefOrGetter<string>) {
  const data = ref<User | null>(null)
  const error = ref<unknown>(null)
  const loading = ref(false)
  let controller: AbortController | null = null

  watch(
    () => toValue(id),
    (userId, _prev, onCleanup) => {
      controller?.abort()
      controller = new AbortController()
      const { signal } = controller
      loading.value = true
      error.value = null
      onCleanup(() => controller?.abort())

      fetch(`/api/users/${userId}`, { signal })
        .then((res) => {
          if (!res.ok) throw new Error(String(res.status))
          return res.json()
        })
        .then((user) => {
          if (signal.aborted) return
          data.value = user
        })
        .catch((err: { name?: string }) => {
          if (err?.name === 'AbortError') return
          error.value = err
          data.value = null
        })
        .finally(() => {
          if (!signal.aborted) loading.value = false
        })
    },
    { immediate: true },
  )

  onScopeDispose(() => controller?.abort())
  return { data, error, loading }
}
```

`onCleanup` chạy khi id đổi và khi watcher dừng. Response chậm của id cũ không được ghi đè id mới. `loading` chỉ tắt cho request còn sống, kẻo request bị hủy làm màn hình tưởng là đã xong.

Ba ô nằm cạnh nhau trong composable. Component chỉ việc đọc:

```vue
<p v-if="loading">Đang tải…</p>
<p v-else-if="error">Không tải được</p>
<p v-else>{{ data?.name }}</p>
```

## 2. Pinia không giữ cache [#wrong-home]

Giỏ hàng là sự thật trên máy người dùng, cho tới khi họ bấm thanh toán. List user vừa fetch là sự thật của server tại một thời điểm. Cất list đó vào Pinia thì bạn phải tự biết lúc nào nó cũ, và `loading` để trong store dễ bị màn khác ghi đè.

`useUser(id)` đủ khi một màn hình sở hữu một request. Nhiều màn cùng một user, cần gộp request trùng, retry, và invalidate sau một mutation, thì đó là việc của một query library. Bài tổng quan nhắc TanStack Query cho đúng lúc đó. Bài này cố ý không cài gì thêm: hình dạng `ref` + `watch` phải rõ trước khi một thư viện giấu nó đi.

<Callout type="warn" title="Bug: list từ server nằm trong Pinia, không có invalidate">
  Store không biết response đã cũ. Hai component fetch hai id vào cùng `users` và cùng `loading` thì cái về sau thắng, kể cả khi nó là request cũ. Để loading, error, data trong `useUser(id)`, và abort trong `onCleanup`.
</Callout>
