## 1. Khi nào dùng store [#when-store]

So với React: composable giống custom hook có `useState` bên trong, mỗi nơi một state. `provide`/`inject` giống context, sống theo cây. Pinia giống Zustand: hàm `useCartStore()` trông như hook, nhưng mọi lần gọi trả về cùng store.

Chọn store khi hai component không có cha chung tiện, mà phải cùng một dữ liệu người dùng đang sửa: giỏ, session đã đăng nhập, bộ lọc dùng ở nhiều layout. Modal của một trang, toggle của một panel, theme của một form thì chưa đáng.

Store cũng là composable theo luật gọi: gọi `useCartStore()` trong setup, không gọi trong click. Pinia gắn store vào app đã `app.use(pinia)`.

## 2. Setup store cho giỏ hàng [#cart-store]

`defineStore` nhận id, rồi một hàm setup hoặc một object option. Với người đang học Composition API, setup store đọc giống component:

```ts
export const useCartStore = defineStore('cart', () => {
  const items = ref<Line[]>([])
  const count = computed(() =>
    items.value.reduce((sum, line) => sum + line.qty, 0),
  )
  function add(line: Line) {
    const found = items.value.find((item) => item.id === line.id)
    if (found) found.qty += 1
    else items.value.push({ ...line })
  }
  return { items, count, add }
})
```

`ref` thành state, `computed` thành getter, function thành action. Pinia yêu cầu return mọi state. Ref tạo trong store mà không return thì không được coi là state: devtools, plugin và SSR không thấy nó.

Trong component, `store.count` và `store.add()` dùng được ngay. Store là `reactive`, nên template đọc `store.count` không cần `.value`. Đừng destructure. Mục sau là đúng cái bẫy đó.

Getter là chỗ của `total`. Đừng giữ một ref tổng rồi tự cộng trong từng action. Action là chỗ sửa state. Đừng fetch danh sách server vào store này. Bài 11 nói vì sao.

## 3. storeToRefs [#store-to-refs]

`const { count } = store` lấy số ra khỏi Proxy, cùng bệnh với `reactive` ở Bài 2. Template đọc biến đó thì đứng yên, dù `store.increment()` đã chạy.

`storeToRefs(store)` trả ref cho state và getter, bỏ qua action. Action destructure thẳng từ store vẫn ổn, vì Pinia đã bind `this`:

```ts
const store = useCartStore()
const { count } = storeToRefs(store)
const { add } = store
```

Giữ `store.count` trong template cũng đủ nếu bạn không cần tách từng field ra. `storeToRefs` đáng khi đưa state vào một composable khác, hoặc khi template của bạn muốn vài biến ngắn.

<StoreToRefsTrap />

<Callout type="warn" title="Bug: destructure store không qua storeToRefs">
  `const { items, count } = useCartStore()` chụp giá trị tại dòng đó. Giỏ thêm món, hai biến không đổi. Dùng `store.items`, hoặc `const { items, count } = storeToRefs(store)`.
</Callout>
